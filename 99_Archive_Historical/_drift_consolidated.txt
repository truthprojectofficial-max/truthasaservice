## 3. Workspace Hygiene (Must Run First on Any New Machine)

These five steps resolve the exact failures described in the unprivileged research (Git 128, 0-byte truncations, Defender blocks, OneDrive locking, multi-SID admin/user problems).

Run **as Administrator** once per machine/workspace:

```powershell
# 1. Full permissions on the clean workspace
icacls "C:\LDDE-Work" /grant:r Everyone:(OI)(CI)F /T /Q

# 2. Global Git safe directory override
git config --global --add safe.directory '*'

# 3. Whitelist Python (add your actual python.exe path)
Add-MpPreference -ControlledFolderAccessAllowedApplications "C:\Program Files\Python313\python.exe"
Add-MpPreference -ControlledFolderAccessAllowedApplications "C:\Program Files\Python312\python.exe"

# 4. Whitelist PowerShell 7 + Windows PowerShell
Add-MpPreference -ControlledFolderAccessAllowedApplications "$env:ProgramFiles\PowerShell\7\pwsh.exe"

# 5. Create standard substructure
$folders = 'scripts','agents','ollama-workspace','logs','artifacts','research'
$folders | ForEach-Object { New-Item -Path "C:\LDDE-Work\$_" -ItemType Directory -Force | Out-Null }
```

**Rule**: Active LDDE projects live under `C:\LDDE-Work` or directly on the external SSD root. OneDrive is for documents only.

## 4. Day-Zero Zero-Touch Provisioning Sequence

Exact phased bootstrap for pristine Windows 11 → full LDDE (WSL2 + Docker + Ollama + external SSD binding).

### Phase 1: Hypervisor & WSL Framework (Reboot Required)
```powershell
dism.exe /online /enable-feature /featurename:Microsoft-Windows-Subsystem-Linux /all /norestart
dism.exe /online /enable-feature /featurename:VirtualMachinePlatform /all /norestart

# <USER_ACTION_REQUIRED> Reboot now, then rerun script with RunOnce or manual resume
wsl --install --no-distribution
wsl --set-default-version 2
```

**Cloud-init bypass** (pre-stage before first distro launch):
```powershell
$cloudInitDir = Join-Path $env:USERPROFILE ".cloud-init"
New-Item -ItemType Directory -Path $cloudInitDir -Force | Out-Null

$userData = @"
#cloud-config
users:
  - name: jdoe
    gecos: Local LDDE User
    groups: [adm,sudo]
    shell: /bin/bash
    lock_passwd: true
    sudo: ALL=(ALL) NOPASSWD:ALL
"@
Set-Content -Path (Join-Path $cloudInitDir "Ubuntu-24.04.user-data") -Value $userData
```

### Phase 2: Headless Dependency Installation (Winget)
```powershell
winget source update --accept-source-agreements

$tools = @(
    "Docker.DockerDesktop",
    "Ollama.Ollama",
    "Git.Git",
    "Python.Python.3.12"
)

foreach ($tool in $tools) {
    winget install --id $tool --silent --accept-package-agreements --accept-source-agreements
}
```

**Docker Desktop invisible install** (if manual):
```powershell
Start-Process -FilePath "Docker Desktop Installer.exe" -ArgumentList "install","--quiet","--accept-license","--backend=wsl-2","--always-run-service" -Wait -NoNewWindow
net localgroup docker-users $env:USERNAME /add
```

### Phase 3: External SSD Binding (Critical)
```powershell
$nextechDisk = Get-WmiObject Win32_DiskDrive | Where-Object { $_.Model -match "Nextech" }

if (-not $nextechDisk) { Write-Error "External SSD not detected"; return }

# Traverse to drive letter (dynamic)
$partition = Get-WmiObject -Query "ASSOCIATORS OF {Win32_DiskDrive.DeviceID='$($nextechDisk.DeviceID)'} WHERE AssocClass = Win32_DiskDriveToDiskPartition"
$logicalDisk = Get-WmiObject -Query "ASSOCIATORS OF {Win32_DiskPartition.DeviceID='$($partition.DeviceID)'} WHERE AssocClass = Win32_LogicalDiskToPartition"
$driveLetter = $logicalDisk.DeviceID

$ollamaPath = Join-Path $driveLetter "OllamaModels"
$workspacePath = Join-Path $driveLetter "LDDE-Workspace"

New-Item -Path $ollamaPath,$workspacePath -ItemType Directory -Force | Out-Null

[System.Environment]::SetEnvironmentVariable("OLLAMA_MODELS", $ollamaPath, "Machine")
$env:OLLAMA_MODELS = $ollamaPath
```

**wsl.conf metadata fix** (for Docker bind mount ownership):
```powershell
$wslConf = @"
[automount]
enabled = true
options = "metadata,umask=22,fmask=11"
mountFsTab = true
"@
$wslConf | wsl -d Ubuntu-24.04 --exec bash -c "cat > /etc/wsl.conf"
wsl --shutdown
```

## 5. Agentic & Prompting Standards

**PTCF Framework** (apply to every complex task)
- **P**ersona: Senior Local-First Engineer on 8GB VRAM MSI hardware, obsessed with determinism and zero-touch.
- **T**ask: Extremely precise success criteria + constraints.
- **C**ontext: Real directory scan + the four research files + current hardware state.
- **F**ormat: Constrained (JSON schema, strict heredoc, minimal file count, TDD skeleton).

**TDD + Jesus Code Verifier Loop**
1. Write test / acceptance check first.
2. Verify it fails.
3. Minimal implementation.
4. Verify success.
5. On error → map to semantic {code, userMessage, recoveryHint}.

**File Operations Discipline**
- Never write directly into OneDrive paths.
- Prefer atomic patterns.
- Always produce reversible scripts for cleanup/moves.

**Grounded Verification & Repeatable Fact Standards** (drawn from Verified.pdf + existing research)

When building agents, scaffolds, or any code that produces claims, decisions, or transformations:

- **Primary Source Preference**: Always keep or reference the original/raw data. Generated output is secondary. Log the chain of custody.
- **Grounded Theory Loops** (adapted for agents):
  1. Open Coding — Break task/output into small verifiable units.
  2. Constant Comparison — Cross-check new output against previous grounded results and real files.
  3. Theoretical Saturation — Only stop when additional checks no longer reveal new contradictions or gaps.
  4. Memoing / Audit Trail — Explicitly document why a decision was made (this becomes the "Jesus Code" recovery context).
- **Fight Linguistic Ambiguity**: When the agent produces vague language ("should", "probably", "might"), force disambiguation or flag it. Prefer explicit uncertainty over false certainty.
- **Auditability First**: Every non-trivial change must be traceable (similar to Wikipedia edit history or research diaries). Include timestamps, source references, and rationale.
- **Systematic Verification Mindset**: Apply lightweight versions of peer-review / PRISMA-style thinking — define success criteria upfront, document the selection process for facts/code, and make it falsifiable.

These standards turn the agent from a fluent generator into a system that produces **grounded repeatable use as information**.
