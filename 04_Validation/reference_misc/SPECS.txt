2. FUNCTIONAL SPECIFICATIONS
================================================================================

F-01. **Determinism.** The build is bit-for-bit deterministic. Same
      input + same config produces the same output, on any host, every
      time. Verified by the boundary test, the normalize test, the
      orchestrator determinism test, the chain re-derivation, and
      the "two orchestrator instances, same input" comparison.

F-02. **No black boxes.** Every number on screen is derived from a
      publicly inspectable formula or rule. No LLM, no model server,
      no embedding, no vector DB, no closed-source library in the
      request path. Verified by the boundary test AST scan + the
      `urllib` / `requests` / `http.client` / `socket` import scan
      (zero matches in 02_Technical/).

F-03. **Truth Ledger.** Every state change is sealed to a SHA-256
      Merkle chain with an ISO 8601 timestamp. The chain is portable,
      tamper-evident, and verifiable offline. Re-derivation runs in
      < 1 ms per block on the canonical host. Verified by `verify` REPL command.
      Live snapshot 2026-07-17: 4,816 blocks, root
      6b1b19aaaecdcc58386863ce44d98a3322b6fba770f6faaa8072f899bd6d828c
      (matches printed paper card).

F-04. **Tau Firewall.** A single input cannot consume more than 10%
      of the system tolerances in any single cycle. The firewall is
      enforced by the runtime, not by the operator. Verified by the
      `tau_firewall.py` unit test + the orchestrator's three-gate
      check.

F-05. **54-pattern deception ontology v3.9.** The build's
      deception-detection surface. 54 patterns (DD-001 to DD-054),
      15 CRITICAL, 35 HIGH, 4 MEDIUM. Every pattern is a substring
      match on the input text. The ontology is content-stable;
      adding a pattern is a forward-compatible change via a
      `DECEPTION_ONTOLOGY_VERSION` bump.

F-06. **BBFB engine (Barnett Binary Faith-Basis).** LAW (multiplicative
      veto, 6 gates), GRACE (quadratic penalty, 3 inputs), FRUIT
      (weighted product, 4 weights), CVS (composite value score,
      threshold 0.0005). Pure Python, no library dependencies. Outputs
      are reproducible to 6 decimal places.

F-07. **Real-Options lattice (Cox-Ross-Rubinstein).** Two-stage
      compound binomial. 11 hardcoded defaults: S0=55.0, K1=18.0,
      K2=10.0, T1=T2=3.0, r=0.05, sigma1=0.30, sigma2=0.20, n1=n2=3,
      learning_delta=10.0, striking_ratio=0.85. Volatility adjusts
      deterministically from the deception score + entropy. No
      random number generator.

F-08. **Ten named modules (5 core agents + 5 supporting).** The five
      core agents: Form_Entry_Agent, Audit_Review_Agent,
      Lattice_Compute_Agent, Ledger_Seal_Agent, Affidavit_Agent. The
      five supporting modules: InventoryAgent (read-only drive
      classifier, sealed to the chain), MonitorAgent (human-in-the-loop
      Incident Briefing, see F-15), Orchestrator (single runtime
      entry point, see F-10), AgentJobDelegator (MCP hand-off, see
      F-09), TauFirewall (10% extraction ceiling, see F-04). All ten
      are deterministic, no LLM in the audit path, sealed to the
      chain via the orchestrator.

F-09. **MCP job delegator.** Agent-to-agent hand-off via
      SHA-256-of-canonical-JSON job tokens. URN format:
      OGIR:<SPACE>:<ACTION>. Spatial map: 00_Strategy,
      01_Methodology, 02_Technical, 03_Vault, 04_Validation, 99_Archive.

F-10. **Orchestrator.** Single runtime entry point. Wires the seven
      agents in sequence. Returns a three-gate verdict (deception,

       < 1 ms for a 220-block chain. The full audit cycle (orchestrator

       substring match is O(N) per pattern. The Real-Options lattice

       outbound network. The boundary test enforces this by AST

       backup agent.
