WHAT TO DO IF SOMETHING BREAKS
==============================
(This is a 1-page index. The full failure-mode catalog is
in 04_Validation/TROUBLESHOOTING.md -- consult that
first; the recipes below are the highest-frequency ones.)
1. From the project root, run the standard opening ritual:
     python -m pytest tests/ -q
   Expected: 86 passed, 1 skipped (the skip is the Ollama
   tool-calling end-to-end test, which needs a tool-capable
   model loaded and FastAPI running on 127.0.0.1:3000). A
   0-collected result means an import error -- read the
   traceback's first line; the file and line number it
   names is the regression. See TROUBLESHOOTING entry 2.1.
2. Re-derive the Merkle chain:
     cd 02_Technical  &&  python -m src.verify_chain
   Expected: "RESULT: MATCH -- chain is intact." If the
   chain is broken, do not run any further audit. Roll
   back to the last sealed state and re-burn from USB.
   See TROUBLESHOOTING entry 1.1.
3. If the FastAPI server will not start on 127.0.0.1:3000,
   check the port: `netstat -an | findstr :3000` (Windows)
   or `lsof -i :3000` (POSIX). Another process owns the
   port if you see a LISTEN row that is not python.exe.
   Free the port or run with `--port 3001` and adjust the
   browser URL. See TROUBLESHOOTING entry 3.2.
4. If the FastAPI server starts but the browser shows
   JSON instead of HTML, the bug class is the one that
   previously hit operator on 2026-07-17: a path bug in
   02_Technical/src/server/app.py STATIC_DIR. Confirm
   with `curl http://127.0.0.1:3000/`. A JSON
   `{"status": ...}` response (instead of HTML) means
   STATIC_DIR did not resolve. The fix is
   `Path(__file__).parent.parent.parent / "web"`. The
   regression test tests/test_static_dir.py catches this.
   See TROUBLESHOOTING entry 3.1.
5. If the Tauri desktop shell opens but the page is
   blank, see TROUBLESHOOTING entry 5.1.
6. If the USB mirror verify_chain returns a different
   root than the source chain verify_chain, the USB is
   stale. Re-mirror with robocopy /MIR per
   HARD_COPY_BACKUP_PLAN_1-2-3.txt Step 1.3. See
   TROUBLESHOOTING entry 4.1.
7. If a single audit gives a different verdict on text
   that previously returned the same verdict, do not
   trust the output. Roll back to the last printed
   Merkle root and re-burn the build from USB. See
   TROUBLESHOOTING entry 1.3.
