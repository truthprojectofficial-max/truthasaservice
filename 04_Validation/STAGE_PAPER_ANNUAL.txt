This is the runbook for the ANNUAL cycle. Print it. Pin it next
to the laptop. Run it on the first Monday of January. This is a
two-day job, not an afternoon. The version bump is the only
maintenance event that changes the project's identity.

--------------------------------------------------------------------------------
THE ONE-LINE SUMMARY
--------------------------------------------------------------------------------
  16 hours (two full days). Re-read every project doc. Run every
  test. Re-burn the USB. Print a fresh paper card. Test the offsite
  copy. Bump PROJECT_VERSION. Seal an ANNUAL_REVIEW block.

--------------------------------------------------------------------------------
TRIGGER
--------------------------------------------------------------------------------
  - First Monday of January.

--------------------------------------------------------------------------------
THE STEPS (tick as you go)
--------------------------------------------------------------------------------

PART A  --  FULL DOCUMENT RE-READ (6 hours)
--------------------------------------------------------------------------------

  [ ] 1. Read 04_Validation/changelog.log from the past year.
        Summarise the year:

          - Total Squeal reports.
          - Total type: "change" entries.
          - Total type: "incident" entries.
          - Total type: "rollback" entries (zero is normal).
          - Total type: "discovery" entries.
        Write this summary to a new file:
        04_Validation/ANNUAL_REVIEW_<YYYY>.md
        (Where <YYYY> is the year that just ended.)

  [ ] 2. Re-read every document in 00_Strategy/:
          - STRATEGY.md (the mission, the scope, the six
            non-negotiables)
          - GOVERNANCE.md (the four gates, the boundary rules)

  [ ] 3. Re-read every document in 01_Methodology/:
          - DECEPTION_ONTOLOGY.md (the 54 patterns, the version)
          - MATHEMATICS.md (the BBFB engine derivation)

            binomial derivation)

  [ ] 4. Re-read every document in 02_Technical/ (skim the .md
        files, the constants, the README, the DEPLOYMENT and
        RESOURCING docs). Confirm the source tree still matches
        what the documentation says.

  [ ] 5. Re-read every document in 04_Validation/ (full list per
        STAGE_PAPER_QUARTERLY step 2). Same drift treatment.

  [ ] 6. Confirm the operator still agrees with all of the above.

        or the maintenance plan -- that is a fork in the project.
        Stop and call a project review.

--------------------------------------------------------------------------------
IF A STEP FAILS
--------------------------------------------------------------------------------
  - any test count drops           -> INCIDENT. Fix before
                                       continuing the cycle.
  - USB stick does not run tests   -> The build is not portable.
                                       STOP. Fix the portability
                                       issue. Re-burn. This is
                                       the most important
                                       verification in the whole
                                       maintenance plan.
  - offsite copy root does not
    match paper card               -> The 1-2-3 backup is broken.
                                       Re-burn the offsite stick.
                                       Update the paper card.
                                       Re-test.
  - onyx> seal fails               -> Check the payload JSON. Try
                                       again. If it still fails,
                                       INCIDENT.
  - operator no longer agrees
    with a project doc             -> That is a fork. STOP the
                                       annual cycle. Call a
                                       project review. The annual
                                       cycle is not the place to
                                       fix a philosophical
                                       disagreement with the
                                       project's foundations.

--------------------------------------------------------------------------------
WHAT THIS CYCLE DOES NOT DO
--------------------------------------------------------------------------------
  - Does NOT run a one-off audit. (That's the weekly cycle.)
  - Does NOT touch the constants outside the version bump.
    (That's the monthly cycle.)
  - Does NOT change the maintenance plan. The maintenance plan
    is the contract. Changing the contract requires a separate
    `MAINTENANCE_PLAN_AMENDED` seal, not an annual cycle.

--------------------------------------------------------------------------------
ANNUAL CADENCE CHECK
--------------------------------------------------------------------------------
  1 cycle/year. 16 hours per cycle. 16 hours/year total operator
  time on annual maintenance. A$32-52/year in materials.
